# Admin 身份与管理员逐项授权

日期：2026-11-09。基于 `d69f1f5`；状态：待用户审阅，尚未实施。

## 已确认的需求

- 新增显示名称为 **Admin** 的最高身份组，高于现有“管理员”。保留管理员、班委、学生和未登录游客。
- 第一个 Admin 指定给现有登录账号 **Akiyy**，不修改其密码。
- Admin 按具体操作给每位管理员分别分配权限，例如查看完整班费、记账、导出独立控制。
- 不改变班费仅记录、不发生真实收支的原则；文件继续存储于腾讯云 COS。

## 方案选择

1. 所有管理员共用权限配置：维护简单，但无法按人员分工。用户未选择。
2. **每位管理员保存自己的操作权限清单：用户选择此方案。** 界面按模块展示复选框，同一管理员可同时管理多个模块，权限可单独收回。

沿用 React、Fastify、SQLite；实现者建议建立前后端共享的权限目录，后端统一判定有效能力，避免继续依赖零散的角色比较。不引入额外身份认证服务，也不增加可由用户任意定义的角色或角色继承系统。

## 身份与管理边界

- 内部角色使用 `super_admin`，界面显示 `Admin`；保留原 `admin` 对应“管理员”，避免名称冲突。
- Admin 拥有全部系统权限，包括创建、停用、修改管理员账号及其权限，任免 Admin，管理班委和学生。
- **管理员与 Admin 账号的创建、任免、权限分配、停用及密码重置，仅 Admin 可执行。** 普通管理员不能修改自己或其他管理员的权限，也不能通过创建账号、批量导入、重置密码或更改角色取得更高权限。
- 普通管理员获得相应账号管理权限后，只能管理班委和学生；给班委授予班费维护资格是单独的 Admin 专属操作，避免管理员借班委身份绕过自己的班费限制。
- 班委的固定管理能力可能超过某位受限管理员。创建、启用、重置密码或调整身份等可获得目标账号能力的操作，还要求目标账号的有效管理能力不超过操作者；否则只能由 Admin 处理。此规则包括已有财务授权的班委和批量操作，须在任何写入前检查。不能借创建或接管班委账号获得本人已被收回的权限。学生账号仍按对应账号操作权限管理。
- 至少保留一名启用的 Admin。禁止停用或降级最后一名 Admin；用户并行修改时也要在同一事务内检查。
- Admin 和管理员均保留“是否纳入班级名单”选项。默认不参与班级提交和缴费名单；仅明确纳入后参与。升级 Akiyy 时保留其原 `inClass` 值和历史记录。
- 班委、学生、游客沿用现有权限。普通管理员未获管理授权时仍保留普通登录成员能查看的已发布内容、公示记录、本人资料及符合名单资格的提交能力；不会因缺少管理权限而丧失本人账号访问。

## 操作权限目录

以下为建议的首版完整清单；界面可以按模块全选或清空，但后端保存和核验各独立条目。

| 模块 | 可分别授予管理员的操作 |
| --- | --- |
| 作业公告 | 查看草稿；创建；编辑内容；发布/恢复发布；撤回；归档；查看参与名单；调整参与名单；查看全班提交；导出表格；打包提交附件 |
| 事务办理 | 与作业对应的 11 项，单独授权，不共享作业的授权 |
| 课程表 | 查看模板；新建备用模板；编辑备用模板；应用模板；编辑当前课表；新增/修改临时调整；移除临时调整 |
| 资料中心 | 查看草稿；查看归档；查看历史版本；新增；编辑；发布/恢复发布；归档 |
| 班费 | 查看完整明细；查看修订历史；新增账目；修订账目；作废账目；新增缴费事项；编辑缴费事项；新增实缴；修订实缴；作废实缴；导出 |
| 班级信息 | 修改班级设置/简介/照片；维护成员展示资料/头像；维护值日安排 |
| 成员账号 | 查看班委和学生账号；创建账号（含批量）；编辑基本资料；调整班委/学生身份；启用/停用；重置密码 |

普通成员查看已发布内容、公开课表、本人历史提交及修改本人密码/头像等不作为可授予的管理员特权。Admin 专属权能不出现在普通管理员权限清单中。

### 权限依赖与复合操作

- 能编辑不等于能发布。直接创建已发布作业/事务需要创建与发布权限；修改已发布内容需要编辑与发布权限；归档、撤回、恢复根据实际状态变化分别校验。资料的创建、修改、发布也使用相同原则。
- 资料中心新增草稿状态，使只有新增/编辑权限的管理员可以保存草稿，交由具有发布权限的人发布。既有已发布/归档资料状态不变；无草稿读取权限的人不能查看。创建表单只有具备发布权限时才可选择立即发布，后端不因旧默认值而绕过该检查。
- 修改当前使用的课表，无论从“编辑当前课表”还是模板列表进入，都需要编辑当前课表权限。新建备用模板不能切换当前课表，切换必须具备应用权限。
- 读与写保持可解释的依赖：需要查看对象才能修改它。界面在勾选写操作时显式勾选所需的最小读取项，取消读取项会清除依赖它的权限；后端拒绝不满足依赖的权限配置，不默默扩大授权。
- 任务编辑只需知道是否已有提交，以锁定表单字段；任务数据返回 `hasSubmissions`，不为编辑器额外读取全班答案。导出表格保留完整参与名单工作表，因此要求同时具备查看全班提交与查看参与名单；附件打包要求查看全班提交，不能额外暴露未提交人员。调整名单依赖查看名单。
- 班费写操作、导出和查看历史依赖查看完整明细；不把“查看完整明细”自动视为可写。公示台账和本人缴费信息仍遵循现有规则。
- 同一请求修改多个部分时，每部分都须授权，例如修改班级设置不能顺带修改成员资料或值日安排。权限不满足时整次请求失败并回滚。

## 附件、导出与隐私

- 元数据、上传、确认、绑定、下载、预览和导出文件的读取均复用所属模块的权限，不提供能绕过模块限制的通用“文件管理”授权。
- 新建作业/事务的暂存附件加入经服务端校验的业务种类上下文，以区分作业和事务；已有任务从数据库取种类，不能信任客户端声明。确认和绑定时再次核验权限、归属和业务状态。
- 班费凭证上传需携带账目/实缴操作上下文；创建、修订和公开凭证仍按实际操作检查权限，历史凭证遵循完整明细/历史读取范围。
- 导出记录保存模块及具体导出能力，用户获得文件 ID 也不能绕过权限。取消导出授权后不能再取得新的下载链接；之前签发的短期 COS 链接维持既有到期规则。
- 本人头像仍可自行修改；改别人头像需要成员展示资料权限，且不能借此覆盖受保护 Admin/管理员账号的身份资料。
- 前端隐藏无权限入口，后端逐个接口和对象检查，拒绝伪造请求。普通管理员无读取授权时，草稿、归档资料、他人提交和私有班费数据不得随列表接口泄漏。

## 权限管理交互

- Admin 的“账号与权限”页面可创建管理员，打开某位管理员的“操作权限”，按上述模块逐项勾选、全选、清空并保存。
- 列表显示身份、启用状态、已授权条目数量和班级名单资格。普通管理员不再显示“全部管理权限”，个人账号页可查看自己的有效授权。
- 分配权限时展示最小依赖，保存后立即反映在后续服务端请求。记录操作人、目标账号、前后权限和时间。
- 普通管理员账号页仅展示自己有权操作的班委/学生及按钮；未授权的字段后端拒绝，而不是只依赖前端禁用。
- 权限更新采用版本检查，避免两个 Admin 覆盖彼此修改；客户端在进入页面、恢复窗口焦点和遇到授权失效时刷新身份与权限，后端始终使用数据库中的最新状态。

## 数据结构与升级建议

- 迁移用户角色约束以接纳 `super_admin`；新增管理员权限存储及授权版本。统一保留原用户 ID、密码哈希、头像资料、成员资格、会话关联、提交、账目和审计数据。
- 升级前备份 SQLite。迁移需可重复执行并在事务中校验完整性；修改用户表时按 SQLite 外键约束迁移流程处理，迁移失败不得留下半成品。
- **首位 Admin 通过一次性服务器命令指定 `Akiyy` 提升。** 命令仅接受已存在且启用的管理员账号，在首次引导时执行并留痕，账号不存在则明确报错，不创建默认账号、不改密码、不自动提升其他管理员。新安装的 setup 直接创建 Admin。
- 现有其他管理员建议显式迁移为全部业务操作及班委/学生账号管理权限，保持业务连续性；管理员任免、管理员改密、权限分配和班委财务授权改为 Admin 专属。Admin 之后可逐项收回。
- 新建管理员默认无管理权限，创建时由 Admin 明确勾选。用户从管理员降为班委/学生后清除管理员授权；再次升回管理员不自动恢复旧权限。新增加的权限条目不会自动授予已有普通管理员。
- 引导命令与迁移不执行真实班级业务操作；保留现有 `.env` 和 COS 配置。部署文档明确备份、更新代码、执行首次提升、构建与重启顺序。
- 现有站点首次升级在维护窗口内停止服务、备份数据库、更新代码和依赖、执行 Akiyy 首次提升、构建、再启动。首次提升失败时修正原因后重试，不把任意现有管理员自动作为替代 Admin；迁移可留在已成功提交状态，业务数据不回退或重建。

## 验收范围

1. 旧库迁移保持账户与业务外键完整，重复启动不重复迁移；Akiyy 提升准确，其他用户不被提升，最后一名 Admin 受到保护。
2. 两名管理员获得不同授权，在相同会话中表现不同；撤权后新请求立即拒绝，无须依赖重新登录；并发授权操作不会互相覆盖。
3. 每项操作覆盖允许与拒绝，检查复合字段、状态转换、导出、上传确认/绑定以及旧文件读取，封堵绕过路径。
4. 普通管理员无法创建或重置更高身份，无法改自身授权，无法在批量导入、头像、班级资料更新或角色修改中越权。
5. 班委的现有管理能力、指定财务班委限制、学生与游客只读范围均回归通过；Admin/管理员的 `inClass`、头像 GIF、作业提交与班费仅记账继续正常。
6. 前端按具体操作展示按钮与弹窗，权限页可保存并刷新；全套测试与生产构建通过，浏览器验证可用时使用隔离合成数据验收。
